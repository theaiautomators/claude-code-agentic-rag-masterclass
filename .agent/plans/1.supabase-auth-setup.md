# 1. Supabase + Schema + RLS (Module 1, part 1 of 3)

✅ **Simple** - Single-pass executable, low risk

## Context
Module 1 (App Shell + Observability) covers Supabase auth, a threaded chat UI, a FastAPI backend that streams replies from the OpenAI Responses API (managed conversations + `file_search`), and LangSmith tracing. This plan sets up local Supabase and the database schema. The next plans are `2.backend-chat-api.md` and `3.frontend-chat-ui.md`.

**Decisions:** local Supabase CLI, email + password auth, documents come from an OpenAI vector store set in env (no upload UI in Module 1). Module 2 replaces the Responses API with Chat Completions (Option A), so OpenAI-specific columns are kept separate.

## Prerequisites
- Docker Desktop is installed and running. `Bash(docker:*)` and `Bash(supabase:*)` are allowed in `.claude/settings.json`.
- The Supabase CLI is installed (`brew install supabase/tap/supabase`).

## Tasks

### 1. Initialise and start Supabase
- Run `supabase init` in the repo root, then `supabase start`.
- Record the API URL and anon key from `supabase status`. They go in `backend/.env` and `frontend/.env.local` in later plans. Never use the service key in app code.
- **Validate:** `supabase status` shows all services running, and Studio loads at http://localhost:54323.

### 2. Chat schema migration
Create `supabase/migrations/<timestamp>_module1_chat.sql`:
- `threads`
  - `id uuid primary key default gen_random_uuid()`
  - `user_id uuid not null default auth.uid() references auth.users on delete cascade`
  - `title text`
  - `openai_conversation_id text`. This is OpenAI-specific and Module 2 drops it.
  - `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`
- `messages`
  - `id uuid primary key default gen_random_uuid()`
  - `thread_id uuid not null references threads on delete cascade`
  - `user_id uuid not null default auth.uid() references auth.users on delete cascade`
  - `role text not null check (role in ('user','assistant'))`
  - `content text not null`
  - `created_at timestamptz not null default now()`
  - In Module 1 this table is for display only, since OpenAI's conversation holds the model's memory. Module 2 reuses it as the real chat history.
- Indexes: `threads(user_id, updated_at desc)` and `messages(thread_id, created_at)`.
- **Validate:** `supabase db reset` applies the migration cleanly, and both tables show up in Studio.

### 3. Row-Level Security
In the same migration:
- `alter table ... enable row level security` on both tables.
- Add separate select/insert/update/delete policies for the `authenticated` role on each table, `using (user_id = auth.uid())`, with `with check (user_id = auth.uid())` on insert and update.
- **Validate:** in the SQL editor, create users A and B (or sign them up through the auth API) and insert a thread as A. Then run `set role authenticated; select set_config('request.jwt.claims', '{"sub":"<B uuid>","role":"authenticated"}', true); select * from threads;` and confirm it returns 0 rows. Running it again with A's uuid should return 1 row.

### 4. Auth config
- Make sure email sign-up is on and email confirmation is off for local dev in `supabase/config.toml` (`[auth.email] enable_confirmations = false`, the default). Set `site_url` to `http://localhost:5173`.
- **Validate:** `curl -X POST "$SUPABASE_URL/auth/v1/signup" -H "apikey: $ANON_KEY" -H "Content-Type: application/json" -d '{"email":"a@test.dev","password":"password123"}'` returns an `access_token`.
