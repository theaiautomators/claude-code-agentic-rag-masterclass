# Module 1: App Shell + Observability

**Complexity:** ⚠️ Medium

## Context

This is the first module of the Agentic RAG masterclass. No application code exists yet — only docs (PRD.md, CLAUDE.md, etc.). We're building the foundational app shell: authentication, a chat UI, OpenAI Responses API integration (managed threads + memory), and LangSmith observability.

The user has a **local Docker Supabase instance** (self-hosted) and an **OpenAI API key**. LangSmith needs to be set up (free tier).

## Database Schema

**File:** `supabase/migrations/001_module1_schema.sql`

### Tables

**threads**
| Column | Type | Notes |
|--------|------|-------|
| id | uuid (PK) | auto-generated |
| user_id | uuid (FK → auth.users) | cascade delete |
| title | text | default 'New Chat' |
| openai_response_id | text | last response ID for conversation chaining |
| created_at | timestamptz | |
| updated_at | timestamptz | auto-updated via trigger |

**messages**
| Column | Type | Notes |
|--------|------|-------|
| id | uuid (PK) | auto-generated |
| thread_id | uuid (FK → threads) | cascade delete |
| user_id | uuid (FK → auth.users) | cascade delete |
| role | text | 'user' or 'assistant' |
| content | text | |
| openai_response_id | text | response ID that produced this message |
| token_usage | jsonb | {prompt_tokens, completion_tokens, total_tokens} |
| created_at | timestamptz | |

### RLS Policies (both tables)
- SELECT: `auth.uid() = user_id`
- INSERT: `auth.uid() = user_id`
- UPDATE (threads only): `auth.uid() = user_id`
- DELETE: `auth.uid() = user_id`

### Key Design Decisions
- `openai_response_id` on threads stores the **last** response ID — used as `previous_response_id` in the next Responses API call for conversation continuity
- Service role key used on backend (bypasses RLS) with explicit `user_id` filters — simpler than passing user JWT to Supabase client
- Cascade deletes: deleting a thread deletes all its messages

## API Endpoints

| Method | Path | Auth | Body | Response |
|--------|------|------|------|----------|
| GET | `/api/health` | No | — | `{"status": "ok"}` |
| GET | `/api/threads/` | Yes | — | `{"threads": [...]}` |
| POST | `/api/threads/` | Yes | `{"title?": "..."}` | `ThreadResponse` (201) |
| GET | `/api/threads/{id}` | Yes | — | `ThreadResponse` |
| DELETE | `/api/threads/{id}` | Yes | — | 204 |
| GET | `/api/chat/{thread_id}/messages` | Yes | — | `{"messages": [...]}` |
| POST | `/api/chat/{thread_id}/messages` | Yes | `{"content": "..."}` | SSE stream |

### SSE Event Format
```
event: text_delta
data: {"content": "Hello"}

event: done
data: {"response_id": "resp_abc123"}
```

## Backend Key Implementation Details

### Auth (`dependencies.py`)
- `get_current_user` dependency: extracts Bearer token, decodes JWT with `SUPABASE_JWT_SECRET` (HS256, audience="authenticated"), returns `{user_id, email}`

### OpenAI Client (`services/openai_client.py`)
- Singleton OpenAI client wrapped with `langsmith.wrappers.wrap_openai()` for automatic tracing
- All LLM calls go through this client — LangSmith traces prompts, responses, latency, tokens automatically

### Chat Service (`services/chat_service.py`)
Core orchestration flow for `POST /api/chat/{thread_id}/messages`:
1. Save user message to Supabase `messages` table
2. Fetch thread's `openai_response_id` for conversation continuity
3. Call `openai.responses.create()` with `stream=True`, `store=True`, `previous_response_id`
4. Yield SSE `text_delta` events as tokens arrive
5. On `response.completed`: save assistant message + token_usage, update thread's `openai_response_id`
6. Yield SSE `done` event

Model: `gpt-4.1`

### LangSmith Integration
- `wrap_openai` auto-traces all OpenAI calls (zero manual instrumentation)
- `@traceable` decorator on `stream_response` for parent chain span
- Environment variables (`LANGSMITH_TRACING`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`) loaded via `python-dotenv` before any imports
- If no LangSmith key is set, tracing is silently disabled — app still works

## Frontend Key Implementation Details

### Auth Flow
- `AuthContext` wraps app, listens to `supabase.auth.onAuthStateChange()`
- `App.tsx`: if no session → `AuthPage`, else → `ChatLayout`
- `AuthPage`: email/password form with login/signup toggle (shadcn Card, Input, Button)
- All API calls include `Authorization: Bearer <access_token>` via `api.ts` helper

### Chat Flow
- `useThreads` hook: fetches thread list, handles create/delete/select
- `useChat` hook: fetches messages for active thread, handles `sendMessage` with SSE streaming
- `sendMessage`: optimistically adds user message to local state, then calls `apiStreamPost` which reads the SSE stream and accumulates text deltas into a growing assistant message
- Auto-scroll to bottom on new messages

### SSE Parsing (`api.ts`)
- Uses `fetch` + `ReadableStream` reader (not EventSource — allows POST + auth headers)
- Parses `event:` and `data:` lines from the stream
- Calls `onDelta(text)` for each text chunk, `onDone()` when complete

### shadcn/ui Components Needed
`button`, `input`, `textarea`, `card`, `scroll-area`, `separator`, `avatar`
